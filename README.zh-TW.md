## 量出來之後最意外的幾件事

**元件沒有固定大小。** 同一個克隆聲音 TTS，在 24 GB 卡上佔 5.1 GB，把卡限制到 8 GB 時只用 2.7 GB——輸出一樣，短句慢 18-26%（視該次執行而定），長句完全沒慢。這打掉了每一份指南都在用的加總法，包括我們自己的初稿：我們先寫了「8 GB 不可能」，然後實測，看著整套堆疊跑在 **7,052-7,615 / 8,192 MiB** 之內。那個錯誤預測還留在文件裡，因為它是我們手上最有力的證據，說明不該用別人的數字去推算你的機器。

**貴的是聲音不是影像。** 大家都在預算對嘴模型。克隆聲音 TTS 佔 5.1 GB，是對嘴服務（2.4 GB）的兩倍多；而使用者的等待時間也花在語音合成上：一句話端到端 11.9 秒，其中對嘴只佔 1.75 秒。

**上下文幾乎跟模型一樣貴。** 從 Ollama 預設的 4096 token 拉到 32k 視窗，8B 模型的佔用**增加 87%**（多 4.4 GB）。伴侶需要人設與對話歷史，所以這筆錢躲不掉。

**在 Windows 上，你的工具會在容量這件事上騙你。** `ollama ps` 回報「17 GB，100% GPU」，實測 delta 是 11.5 GB，而且它一次都沒說過自己分流了。WDDM 驅動會超額配置到系統記憶體而不是失敗，所以沒有 OOM、沒有錯誤，只有一台變慢的機器。**吞吐量是唯一誠實的訊號。**

**駐留便宜，併發才貴。** 一顆 27B 模型駐留著、即使把卡填到 98%，成本量不出來。同一顆模型真的在生成時，讓對嘴慢了 1.6 倍。

**Wav2Lip 的權重禁止商用。** 它正是讓低顯存這個說法成立的模型，也是每一份熱門指南在用的那個。只要有金錢往來，你就需要換一個模型，乾淨的路線寫在 `docs/07-licenses.zh-TW.md`。

## 你需要哪張卡

| 卡 | 配置 | 狀態 |
|---|---|---|
| **8 GB** | 語音＋對嘴本機，LLM 遠端 | ✅ 實測 7,052-7,615 / 8,192 MiB |
| **16 GB** | 全本機，8B 在 32k 上下文 | ✅ 在 32k 實測通過；建議用 16k 留餘裕 |
| **24 GB** | 全本機，8B 在 32k，還有餘裕 | ✅ 直接實測 |
| **32 GB** | — | ⚠️ 只有算術，我們沒有這張卡 |

較小的等級是用 `bench/ballast.py` 佔住顯存、只留下目標容量來測的。那模擬的是**容量**，決定東西載不載得進去、跑不跑得動。它不模擬另一張 GPU 的頻寬，所以「裝得下」可以套用到真實硬體，「有這麼快」不行。

## 量測比看起來難得多

`bench/` 裡每一支工具的檔頭都記著我們先前是怎麼量錯的。摘要如下，因為這些也會咬到你：

- **接在提示詞後面的防快取字串會被念出來。** 在四個字的句子後面接 unix 時間戳，模型就多念了十個數字，讀數被灌大 **3.3 倍**。要改一個不會被念出來的欄位。
- **尾隨空白破不了快取。** 實測：同一句加 3 個和 11 個空白，回傳位元組完全相同，耗時 0.01 秒。
- **破快取的值必須每輪唯一，而且值域要夠大。** 12 個值跨輪碰撞，造成 6/6 全部靜默命中快取。
- **Windows 上沒有 per-process 顯存。** WDDM 之下 `--query-compute-apps` 回 `[N/A]`。差值法是唯一可行的方法。
- **`/health` 回 200 不代表載完。** 有個服務 5 秒就回應，然後花了 4 分鐘搬動 800 MiB。
- **單次顯存 delta 讀不得。** 有一次探測回報 +88 MiB，而它是 0.00 秒從快取回來的，根本沒做任何 GPU 運算。

`suite.py` 拒絕把低於 100 毫秒的回應平均進結果，它會標成快取命中。

## 我們自己的檢查器在自己的片庫上是紅的，而我們讓它保持紅的

    bash player/examples/check-clips.sh   # exit 1
    python player/examples/check-mouth.py 'player/examples/clips/*_still.mp4'         --model face_landmarker.task      # exit 0

樞紐幀檢查器對三套外觀中的一套回報 `ENDS ELSEWHERE`。那套的尾幀離它自己片子起始的
那一格 20 到 22（滿分 255），另外兩套是 12.6。照工具自己的規則那就是缺陷，工具也照實說了。

它是真的、有界的，而播放器用的 120 ms 溶接蓋得掉。成因追過了，記在 `docs/05-assets.md`：
漂移是對嘴引擎在序列末端加上去的，會隨嘴部幅度放大，而同一句話在那套外觀的三種不同來源
上各算一次得到 21.9、20.0、23.5——所以它跟著那張臉走，不跟著來源走。
引擎自己的表情淡出讓它更糟，收在最後幾幀裡最好的那一格也幾乎救不回什麼。

**門檻沒有為了讓它通過而調動。** 一個被調到剛好讓自己的資料過關的量測工具，什麼也沒量到；
而這個 repo 存在的理由，正是因為多數公開數字就是那種東西。
